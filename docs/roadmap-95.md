# My BTC Box 9.5+ 路线图

真实用户、回访和搜索收录的采集口径见 `docs/real-world-validation.md`，不得以自动测试或开发者自评替代。

更新时间：2026-08-11

本路线图服务于 `docs/quality-standard-95.md`。顺序由风险和用户价值决定，不以功能数量决定。

## 已建立的基础

- 首页历史事件查询、周期对照、条件买入回测和报告生成。
- 五币种完整 UTC 日线信号与 BTC 每日观察摘要。
- 公开方法页、数据健康清单和关键计算回归测试。
- 本地保存查询条件。
- 十项质量计分卡及自动结构检查。
- 每日数据更新在提交前运行测试，并同步健康状态文件。

## 阶段一：可信发布链

主要提升：数据正确性、数据运维、数据表达。

- 为工作流失败建立主动通知渠道。
- 增加上游数据抽查，记录抽查日期、交易对、误差和结果。
- 建立数据恢复运行手册和最近成功快照规则。
- 将数据健康页扩展为用户可理解的延迟和异常说明。
- 把“测试通过后才能发布”扩展到所有代码部署。

完成条件：连续 30 天每日更新无静默失败，至少完成一次恢复演练。

## 阶段二：每日回访闭环

主要提升：用户粘性、核心工具价值、报告与分享。

- 每日观察摘要继续作为第一屏回访理由。
- 保存的查询增加清晰的恢复入口和最近查看状态。
- 增加用户主动开启的浏览器提醒，默认关闭，随时可撤销。
- 生成可分享的“今日观察报告”，包含固定链接和数据截止日期。
- 接入隐私友好的匿名事件统计，衡量次日、7 日和 30 日回访。

完成条件：核心回访路径可测量，7 日回访率达到 20%，提醒退订和权限失败均有降级状态。

## 阶段三：独立工具与搜索入口

主要提升：SEO 获客、产品定位、核心工具价值。

- 为历史暴跌、历史暴涨、振幅、插针、周期刻度和条件回测建立稳定 URL。
- 每个页面提供独立标题、描述、canonical、Open Graph 和查询示例。
- 增加 `sitemap.xml`、`robots.txt` 和适用的结构化数据。
- 工具页面保持真实功能，不创建只有关键词没有用途的薄内容。
- 建立 Search Console 和 Core Web Vitals 月度证据记录。

完成条件：所有核心工具可独立索引和分享，无重复 canonical 或结构化数据错误。

## 阶段四：代码模块化

主要提升：代码扩展性、数据正确性、移动端。

- 提取数据访问和标准化模块。
- 提取事件计算、周期计算和回测计算模块。
- 提取首页、查询结果、报告和文案渲染模块。
- 建立统一状态和错误处理，避免模块各自读取全局变量。
- 为模块增加独立测试，并建立性能和文件体积预算。

完成条件：新增币种或新查询类型不需要复制页面，核心计算可在无 DOM 环境独立测试。

## 阶段五：9.5 验收

主要提升：全部十项。

- 完成 360px、390px、430px、平板和桌面端自动验收。
- 完成至少 5 名目标用户的定位理解和核心任务测试。
- 为全部计分项补齐仓库、线上、性能或用户数据证据。
- 任何未通过的验收点都保留原分，修复后重新评估。
- 达到 9.5 后继续观察 30 天；满足全部验收点再评为 10 分。

## 插件和外部工具原则

- 只有在对应验收项明确需要时才引入插件或 Skill。
- 分析工具必须提供隐私说明、最少采集和可关闭方案。
- 外部数据源必须记录交易对、时区、延迟、失败方式和许可边界。
- 第三方库必须有维护状态、体积、安全和可替换性评估。
- 安装工具本身不计分，解决真实验收缺口才计分。
