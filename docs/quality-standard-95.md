# My BTC Box 9.5+ 产品质量标准

更新时间：2026-08-11

## 目标

My BTC Box 的十项产品指标都必须达到 9.5/10 以上，并且每个分数都能由仓库文件、自动化测试、线上页面或真实用户数据证明。

评分不以“功能已经做过”为依据，而以“用户能稳定完成任务，数据可解释，异常可发现，结果可复现”为依据。

## 统一评分方法

每个维度包含 20 个验收点，每点 0.5 分：

- 9.5 分：至少 19 个验收点通过，并且没有阻断级问题。
- 10 分：20 个验收点全部通过，并保持至少 30 天没有阻断级回归。
- 阻断级问题：错误数据、误导性预测、核心工具不可用、移动端无法完成任务、数据更新静默失败、隐私或安全问题。
- 任何分数变化必须同时更新 `quality-scorecard.json` 中的证据，不允许凭印象加分。

每个维度的 20 个验收点分成四组，每组 5 点。某一组只有在对应证据完整时才能获得 2.5 分。

## 十项验收标准

### 1. 产品定位

1. 定位一致性：所有核心页面都明确“历史数据参考，不预测涨跌，不构成建议”。
2. 用户理解：至少 5 名目标用户能在 10 秒内说出网站用途，成功率不低于 80%。
3. 内容边界：不展示无法解释的综合评分，不用确定性语言描述未来价格。
4. 差异化：核心入口围绕历史事件、周期、回测和报告，不复制交易所行情终端。

### 2. 核心工具价值

1. 任务覆盖：用户能完成查历史、做对比、跑回测、生成报告四类核心任务。
2. 可完成性：四类任务的成功率不低于 95%，没有死链或无响应按钮。
3. 结果解释：每项结果都有口径、样本数、日期范围和限制说明。
4. 性能稳定：核心交互 p95 响应低于 1 秒，数据加载失败有明确降级状态。

### 3. 数据表达

1. 来源透明：展示数据源、交易对、时区、日线截止日期。
2. 口径透明：区分收盘涨跌、振幅、插针、最高价和最低价口径。
3. 样本透明：概率、均值和回测结果展示有效样本数及范围。
4. 可复核：关键指标能从公开原始数据和公开方法页独立复算。

### 4. 报告与分享

1. 内容完整：报告包含查询条件、样本数、核心结果、数据日期和风险说明。
2. 分享闭环：支持下载图片、系统分享或复制链接，失败时有降级方案。
3. 跨端质量：微信常用尺寸、手机浏览器和桌面端文字均清晰可读。
4. 可追溯：分享内容带网站地址、生成日期、数据截止日期和查询参数。

### 5. 移动端

1. 适配范围：360px、390px、430px 和常见平板宽度无横向溢出。
2. 可读性：正文不小于 12px，关键结果不小于 16px，对比度达到 WCAG AA。
3. 可操作性：主要点击区域至少 44px，键盘和触控操作都可完成核心任务。
4. 性能：移动端 Lighthouse Performance、Accessibility、Best Practices、SEO 均达到 90 以上。

### 6. 数据正确性

1. 数据校验：OHLCV 顺序、日期连续性、数值范围、重复日期和最新日期自动检查。
2. 计算校验：涨跌、回撤、概率、回测和周期计算有单元或回归测试。
3. 来源抽查：每周自动抽查至少 5 个日期，与上游数据误差在定义范围内。
4. 发布门禁：数据或代码更新必须先通过测试，失败时不得提交或部署。

### 7. 用户粘性

1. 每日价值：用户每天打开都能看到新的完整日线摘要和异常信号。
2. 个性化：查询条件、关注币种和报告偏好可以本地保存并恢复。
3. 回访机制：提供用户主动订阅的浏览器提醒、周报或可安装入口，默认不打扰。
4. 可衡量：在尊重隐私的前提下记录次日、7 日和 30 日回访，7 日回访率目标不低于 20%。

### 8. SEO 获客

1. 页面覆盖：每个核心工具有独立、可索引、可分享的稳定 URL。
2. 搜索基础：标题、描述、canonical、Open Graph、sitemap 和 robots 配置完整。
3. 结构化数据：适用页面使用 WebApplication、Dataset、FAQ 或 Breadcrumb 标记并通过验证。
4. 内容与性能：工具页有原创方法说明和示例，Core Web Vitals 达标，无重复薄内容。

### 9. 数据运维

1. 自动更新：每日任务可重复运行，提交数据前执行完整测试。
2. 健康状态：公开最新日期、延迟、行数、文件更新时间和异常状态。
3. 异常通知：更新、测试或部署失败能主动通知维护者，不允许静默失败。
4. 恢复能力：有运行手册、可回滚版本和最近一次成功数据快照，恢复演练可在 30 分钟内完成。

### 10. 代码扩展性

1. 模块边界：数据、计算、渲染、报告、文案和状态管理分离，首页不再承载全部逻辑。
2. 自动化质量：格式检查、静态检查、测试和构建统一由命令执行并接入 CI。
3. 可替换性：新增币种、数据源或工具不需要复制整套页面逻辑。
4. 文档与预算：架构决策、目录职责、性能预算和发布流程有持续维护的文档。

## 执行顺序

1. 先补数据发布门禁、健康状态和异常通知，避免错误数据扩大影响。
2. 再做回访闭环，包括每日摘要、保存条件、主动订阅和隐私友好的回访衡量。
3. 将核心工具拆成独立可索引入口，同时补齐 sitemap、结构化数据和分享链接。
4. 在功能边界稳定后拆分首页代码，建立可复用的数据与计算模块。
5. 每次上线都更新计分卡证据；没有证据的项目保持原分。

## 证据规则

可接受证据包括：

- 仓库中的自动化测试、工作流、方法文档和运行手册。
- 线上稳定 URL、结构化数据验证结果和 Lighthouse 报告。
- 可复现的数据抽查记录。
- 匿名聚合的真实使用指标和用户测试记录。

不接受的证据包括：

- 只有截图，没有可访问页面或复现步骤。
- 只有功能代码，没有测试或异常状态。
- 由开发者主观判断“体验不错”。
- 为了加分而添加但用户没有实际用途的功能。
